# SCMP — задание 4

## §1. Область применения и роли

Учебный проект «Управление задачами и конфликтами Git», Python 3.11+, локальная работа. Разработчик регистрирует
изменение и пишет код; рецензент рассматривает влияние, принимает решение;
ответственный за выпуск утверждает baseline и версию. В учебной работе роли может
выполнять один человек; независимый контроль и аутентификация отсутствуют.

## §2. Идентификация конфигурационных единиц

CI-SRC: src/, CI-TEST: tests/, CI-META: pyproject.toml и uv.lock,
CI-DOC: README.md, SCMP.md, CHANGELOG.md; для заданий 5–9 CI-PIPELINE: .github/workflows/.
Единица имеет относительный путь, уникальный ID, версию и SHA-256, когда это
предусмотрено предметной областью задания. Git-коммит фиксирует согласованное состояние.

## §3. Контроль изменений и baseline

До изменения утверждённого состояния: зарегистрировать CR, описание и автора,
оценить влияние, получить решение рецензента. Реализовать в feature-ветке,
добавить проверку, получить успешные pytest/ruff, выполнить review и merge.
Номер baseline уникален; утверждающий и дата фиксируются; новую baseline связывают
с предыдущей. Утверждённые снимки не редактируются через приложение.
Для проектов без встроенного реестра baseline её роль играет документированное
состояние Git с тегом; это организационная, а не автоматически принудительная процедура.

## §4. Учёт состояний

CHANGELOG описывает изменения, Git хранит историю, examples/ — демонстрационные
свидетельства. Для встроенного журнала CR используются только допустимые переходы.
Связь CR ↔ commit проверяется по полному SHA; ссылки на тесты сопровождают доказательства.

## §5. Аудит

Проверить состав файлов, ожидаемую версию, результаты тестов и отсутствие
незарегистрированных изменений. Для baseline-инструментов сравнить SHA-256 с утверждённым
состоянием. Функциональный тест проверяет поведение; аудит — соответствие конфигурации
и наличие свидетельств. Успешный CI не означает полного соответствия стандарту.

## §6. Сборка и выпуск

Версия 1.0.0 находится в pyproject.toml; тег v1.0.0 фиксирует локальный выпуск.
Сборка: `uv build`; wheel/sdist устанавливаются через `uv tool install <wheel>`.
Задание 6 проверяет тег только в отдельной релизной сборке. В заданиях 5–9 CI
подготовлен для push и pull_request. Публикация и развёртывание не выполнялись.

## Реализованные практики и границы

SQLite tasks; CRUD, комбинированная фильтрация, статистика. Реальный учебный конфликт задокументирован в CONFLICT_REPORT.md.

Нет сетевой совместной работы, авторизации и уведомлений. Дата — плановая дата задачи, формат YYYY-MM-DD.

Это учебная реализация отдельных принципов ISO/IEC/IEEE 828:2012,
а не заявление о соответствии или сертификации.
